# 사물인식 플랫폼 기획

`rtdetr` 패키지 위에 올리는 웹 애플리케이션. **수집 → 라벨링 → 데이터셋 → 학습 →
평가 → 추론/배포**를 한 화면에서 끝내되, 각 단계의 결과물을 언제든 저장하고
내보내고 다시 들여올 수 있게 한다.

## 원칙

1. **한 대에서 완결.** 프로세스 하나, SQLite 하나, 폴더 하나. 큐 브로커·DB 서버·
   오브젝트 스토리지 없이 뜬다. 공장·매장처럼 데이터가 밖으로 나갈 수 없는 곳이
   1순위 사용처다.
2. **데이터는 사용자 것.** 모든 산출물(데이터셋, 가중치, IR, 지표)은 표준 형식의
   파일로 내려받을 수 있고, 플랫폼 없이도 열린다. 잠금 장치를 만들지 않는다.
3. **모델이 먼저 일한다.** 라벨링·검수·평가 어디서든 모델이 초안을 만들고 사람은
   고친다. 이 플랫폼이 검출기를 내장한 이유가 그것이다.
4. **패키지와 분리.** 엔진(`rtdetr`)은 웹 의존성을 모른다. 이 앱이 패키지를 쓰지,
   패키지가 이 앱을 알지 못한다.
5. **정직한 숫자.** 검증은 학습에 쓰지 않은 이미지로만. 진행 중인 작업을 완료로
   표시하지 않는다.

## 단계별 기능

| 단계 | 하는 일 | 저장 | 내보내기 / 들여오기 |
| --- | --- | --- | --- |
| 수집 | 이미지·영상 업로드, 영상에서 프레임 추출, 로컬 폴더 등록 | 데이터셋 폴더 | zip |
| 라벨링 | 상자 그리기·이동·크기·삭제·되돌리기, 클래스 지정, 모델 자동 라벨 | `labels/*.txt` 자동 저장 | zip (YOLO 형식) |
| 데이터셋 | 목록·통계·검색, 클래스 편집, 학습/검증 분할, 삭제·복제·병합 | SQLite + data.yaml | zip |
| 학습 | 큐, 진행률·곡선, 중지, 백본 고정, 재개 | `runs/job<id>/` | best.pt · results.csv |
| 평가 | 검증셋 예측 미리보기, 클래스별 AP, 틀린 사례 훑기 | 지표 JSON | CSV |
| 추론 | 이미지·폴더·영상·웹캠, conf 조절, 결과 저장 | 결과 폴더 | 이미지·영상·JSON |
| 배포 | OpenVINO IR 내보내기, 모델 레지스트리 | `runs/.../openvino/` | IR zip |

## 현재 상태 (2026-09-08)

**되는 것** — 수집(이미지 다중 업로드 · 영상에서 프레임 추출 · 폴더 등록 · zip 업로드,
기존 데이터셋에 이어붙이기), 라벨링(그리기/이동/크기/삭제/되돌리기/
자동 라벨 단건·일괄, 줌·팬, 이전 상자 복사, 클래스 추가·개수, 라벨 없는 것만 보기), 데이터셋 목록·클래스 편집·삭제·zip 내보내기/들여오기,
학습 큐·에폭 곡선·중지·백본 고정·검증 분할, 산출물 다운로드(best.pt / IR / CSV),
이미지 한 장 추론 미리보기, 재시작 시 유령 작업 정리.

**없는 것** — 아래 로드맵이 곧 이 목록이다.

## 로드맵

### P0 — 지금 없으면 반쪽인 것

1. **평가 화면.** 검증셋에 대한 예측을 정답과 겹쳐 보여주고, 클래스별 AP와 놓친
   사례·오탐 사례를 훑을 수 있어야 한다. 지금은 mAP 숫자 하나뿐이라 "왜 안 되는지"를
   볼 방법이 없다.
   *완료 기준*: 작업 상세에서 검증 이미지 목록 → 정답(초록)·예측(빨강) 겹쳐 보기,
   클래스별 AP 표, conf 슬라이더.
2. **일괄 추론.** 폴더·영상에 대해 추론을 돌리고 결과를 이미지/영상/JSON으로
   내려받기. 지금은 한 장씩만 된다.
   *완료 기준*: 추론도 작업(job)으로 큐에 들어가고 진행률이 보이며, 결과 zip 다운로드.
3. ~~**수집 도구.**~~ **완료** — 이미지 다중 업로드, 영상 → 프레임 추출(간격·장수
   지정), 기존 데이터셋에 이어붙이기. 브라우저에서 이미지 2장 → 영상 5프레임 추가
   → 7장 확인.
4. **모델 레지스트리.** 학습 결과에 이름·설명을 붙여 등록하고, 자동 라벨·추론에서
   그 이름으로 고를 수 있게. 외부 `.pt`/IR 업로드도 같은 목록에 들어온다.
   *완료 기준*: 자동 라벨 모델 선택 상자에 "내 모델 v3"가 뜬다.

### P1 — 쓰다 보면 반드시 요구될 것

5. ~~**라벨링 편의.**~~ **완료** — 휠 줌·가운데버튼/스페이스 팬, <kbd>C</kbd>로 이전
   이미지 상자 복사, 라벨 없는 이미지만 보기, 클래스별 개수, 클래스 추가 UI.
6. **데이터셋 관리.** 이미지 삭제, 데이터셋 복제·병합, 스냅샷(버전).
7. **학습 편의.** 중단된 작업 재개, 하이퍼파라미터 프리셋(빠름/균형/정확),
   실패 원인 요약, 학습 로그 tail.
8. **실시간 미리보기.** 웹캠을 열어 현재 모델로 바로 보기.

### P2 — 여러 사람·여러 장비로 넘어갈 때

9. 인증과 사용자별 격리, 동시 작업·여러 GPU, 작업 우선순위.
10. 배포: 추론 엔드포인트 발급, Docker 이미지, 엣지 에이전트 pull.
11. 운영: 디스크 사용량·보존 정책, 백업/복원.

## 데이터 모델

```
datasets(id, name, path, images_dir, labels_dir, images, labelled, classes, created)
jobs(id, kind, dataset_id, model, epochs, imgsz, batch, freeze, device, conf,
     status, detail, progress, run_dir, best_map, created, started, finished)
epochs(job_id, epoch, loss, map50_95, seconds)
```

`kind`는 `train` · `autolabel`이며 P0에서 `predict`(일괄 추론)가 추가된다.
`status`는 `queued → running → exporting → done | failed | cancelled`.
모델 레지스트리는 `models(id, name, kind, path, job_id, classes, created)`로 붙인다.

## 검증 방식

기능마다 (1) API 테스트, (2) 실제 브라우저 조작 테스트를 남긴다. 지금까지 이렇게
확인했다: 폴더 등록 → 일괄 자동 라벨(12장) → 손으로 상자 추가 → zip 내보내기 →
다시 들여오기(12장·라벨 12) → 학습(9/3 분할, 3에폭) → 산출물 3종 → 추론 200 OK.
이 흐름을 깨는 변경은 머지하지 않는다.
