# 사물인식 플랫폼 기획

`rtdetr` 패키지 위에 올리는 웹 애플리케이션. **수집 → 라벨링 → 데이터셋 → 학습 →
평가 → 추론/배포**를 한 화면에서 끝내되, 각 단계의 결과물을 언제든 저장하고
내보내고 다시 들여올 수 있게 한다.

## 원칙

1. **한 대에서 완결.** 프로세스 하나, SQLite 하나, 폴더 하나. 큐 브로커·DB 서버·
   오브젝트 스토리지 없이 뜬다. 공장·매장처럼 데이터가 밖으로 나갈 수 없는 곳이
   1순위 사용처다.
2. **데이터는 사용자 것.** 모든 산출물(데이터셋, 가중치, IR, 지표)은 표준 형식의
   파일로 내려받을 수 있고, 플랫폼 없이도 열린다. 잠금 장치를 만들지 않는다.
3. **모델이 먼저 일한다.** 라벨링·검수·평가 어디서든 모델이 초안을 만들고 사람은
   고친다. 이 플랫폼이 검출기를 내장한 이유가 그것이다.
4. **패키지와 분리.** 엔진(`rtdetr`)은 웹 의존성을 모른다. 이 앱이 패키지를 쓰지,
   패키지가 이 앱을 알지 못한다.
5. **정직한 숫자.** 검증은 학습에 쓰지 않은 이미지로만. 진행 중인 작업을 완료로
   표시하지 않는다.

## 단계별 기능

| 단계 | 하는 일 | 저장 | 내보내기 / 들여오기 |
| --- | --- | --- | --- |
| 수집 | 이미지·영상 업로드, 영상에서 프레임 추출, 로컬 폴더 등록 | 데이터셋 폴더 | zip |
| 라벨링 | 상자 그리기·이동·크기·삭제·되돌리기, 클래스 지정, 모델 자동 라벨 | `labels/*.txt` 자동 저장 | zip (YOLO 형식) |
| 데이터셋 | 목록·통계·검색, 클래스 편집, 학습/검증 분할, 삭제·복제·병합 | SQLite + data.yaml | zip |
| 학습 | 큐, 진행률·곡선, 중지, 백본 고정, 재개 | `runs/job<id>/` | best.pt · results.csv |
| 평가 | 검증셋 예측 미리보기, 클래스별 AP, 틀린 사례 훑기 | 지표 JSON | CSV |
| 추론 | 이미지·폴더·영상·웹캠, conf 조절, 결과 저장 | 결과 폴더 | 이미지·영상·JSON |
| 배포 | OpenVINO IR 내보내기, 모델 레지스트리 | `runs/.../openvino/` | IR zip |

## 현재 상태 (2026-09-08)

**되는 것** — 수집(이미지 다중 업로드 · 영상에서 프레임 추출 · 폴더 등록 · zip 업로드,
기존 데이터셋에 이어붙이기), 라벨링(그리기/이동/크기/삭제/되돌리기/
자동 라벨 단건·일괄, 줌·팬, 이전 상자 복사, 클래스 추가·개수, 라벨 없는 것만 보기), 데이터셋 목록·통계·클래스 편집·이미지 삭제·복제·병합(클래스 재매핑)·삭제·
zip 내보내기/들여오기,
학습 큐·에폭 곡선·중지·백본 고정·검증 분할·프리셋·이어서 학습·로그,
평가(클래스별 AP + 정답/예측 겹쳐보기), 산출물 다운로드(best.pt / IR / CSV / 로그),
추론(이미지 한 장 · 폴더/데이터셋/영상 일괄 · 웹캠 실시간),
모델 레지스트리(학습 결과 등록 · 외부 .pt/IR 업로드 · 이름으로 선택),
재시작 시 유령 작업 정리.

**없는 것** — P2가 통째로 남았다. 여러 사람이 동시에 쓰는 상황(인증·격리·동시 작업)과
운영(보존 정책·백업), 그리고 학습된 모델을 서비스로 띄우는 부분(추론 엔드포인트·
Docker)은 아직 손대지 않았다.

## 로드맵

### P0 — 지금 없으면 반쪽인 것

1. ~~**평가 화면.**~~ **완료** — 평가를 작업으로 돌려 검증셋 전체에 대해 정답(초록)과
   예측(클래스 색)을 겹친 이미지를 만들고, 클래스별 AP 표와 함께 갤러리로 보여준다.
   각 카드에 "참 N / 찾음 M"이 붙어 놓친 장면이 눈에 띈다.
2. ~~**일괄 추론.**~~ **완료** — 데이터셋·로컬 폴더·업로드한 영상에 대해 추론을 작업
   으로 돌린다. 진행률이 보이고, 끝나면 그린 이미지 zip(`results.json` 포함)과 영상은
   `annotated.mp4`로 내려받는다. 브라우저에서 폴더 4장(상자 26개), 영상 40프레임
   (상자 274개)으로 확인.
3. ~~**수집 도구.**~~ **완료** — 이미지 다중 업로드, 영상 → 프레임 추출(간격·장수
   지정), 기존 데이터셋에 이어붙이기. 브라우저에서 이미지 2장 → 영상 5프레임 추가
   → 7장 확인.
4. ~~**모델 레지스트리.**~~ **완료** — 학습 결과에 이름·메모를 붙여 등록하면(IR이 있으면
   IR을, 없으면 `best.pt`를 가리킨다) 자동 라벨·일괄 추론·웹캠의 모델 선택 상자에 그
   이름으로 뜬다. 외부 `.pt`/`.onnx`/`.xml` 업로드도 같은 목록에 들어온다.

### P1 — 쓰다 보면 반드시 요구될 것

5. ~~**라벨링 편의.**~~ **완료** — 휠 줌·가운데버튼/스페이스 팬, <kbd>C</kbd>로 이전
   이미지 상자 복사, 라벨 없는 이미지만 보기, 클래스별 개수, 클래스 추가 UI.
6. ~~**데이터셋 관리.**~~ **완료** — 이미지 삭제, 복제(실험 전 스냅샷), 병합(클래스
   이름 기준 재매핑), 통계(클래스별 상자 수·라벨 없는 이미지·빈 라벨·아주 작은 상자).
7. ~~**학습 편의.**~~ **완료** — 이어서 학습(에폭 추가), 프리셋(빠름/균형/정확),
   실패 시 로그 꼬리를 원인에 붙임, 실행별 train.log 다운로드.
8. ~~**실시간 미리보기.**~~ **완료** — 브라우저가 웹캠 프레임을 400ms마다 `/api/preview`로
   보내고 그려진 프레임과 검출 요약을 돌려받는다. 카메라는 브라우저 것이므로 서버가
   원격이어도 된다.

### P2 — 여러 사람·여러 장비로 넘어갈 때

9. 인증과 사용자별 격리, 동시 작업·여러 GPU, 작업 우선순위.
10. 배포: 추론 엔드포인트 발급, Docker 이미지, 엣지 에이전트 pull.
11. 운영: 디스크 사용량·보존 정책, 백업/복원.

## 데이터 모델

```
datasets(id, name, path, images_dir, labels_dir, images, labelled, classes, created)
jobs(id, kind, dataset_id, model, epochs, imgsz, batch, freeze, device, conf,
     status, detail, progress, run_dir, best_map, created, started, finished)
epochs(job_id, epoch, loss, map50_95, seconds)
```

```
models(id, name, path, kind, job_id, classes, note, created)
```

`kind`는 `train` · `autolabel` · `evaluate` · `predict`. `status`는
`queued → running → exporting → done | failed | cancelled`. 일괄 추론 작업은
`source`(폴더 또는 영상 경로)와 `conf`를 쓰고, 나머지 학습 열은 비운다.

  YOLO 형식으로 내보내면 그대로 학습된다.

* 학습 알고리즘 연구용 실험 관리(스윕, 분산 학습).

## 검증 방식

기능마다 (1) API 테스트, (2) 실제 브라우저 조작 테스트를 남긴다. 지금까지 이렇게
확인했다: 폴더 등록 → 일괄 자동 라벨(12장) → 손으로 상자 추가 → zip 내보내기 →
다시 들여오기(12장·라벨 12) → 학습(9/3 분할, 3에폭) → 산출물 3종 → 모델로 등록 →
그 이름으로 폴더 일괄 추론(4장·상자 26) · 영상 일괄 추론(40프레임·상자 274,
zip + mp4) · 웹캠 미리보기(가짜 카메라로 검출 확인).
이 흐름을 깨는 변경은 머지하지 않는다.
